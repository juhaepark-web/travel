# 구현 검증 기록 — 2026-10-17

## 2026-10-18 실제 연결 오류 수정

실제 Firebase에서 발급된 토큰 검증이 `Token used too early`로 실패하는 것을 확인했다. PC 시계가 토큰 발급 시각보다 약 7초 느렸다. `verify_id_token`에 `clock_skew_seconds=60`을 적용했으며 서명·프로젝트·만료·폐기·비활성 계정 검증은 유지한다. 실제 프로젝트의 기존 관리자 계정용 진단 토큰으로 서버 토큰 검증과 관리자 권한 판별 통과를 확인했다. 비밀번호는 조회·출력하지 않았다. 사용자 입력 비밀번호로 화면에서 로그인·가입 완료를 다시 확인하는 단계는 남아 있다.

## 자동 검증

Python 문법 검사 및 모든 JavaScript 파일의 node --check 통과.

Firebase Authentication/Realtime Database Emulator (demo-travel)와 Python 테스트 API 서버에서 `python -m unittest discover -s tests -p test_emulator.py -v` 12개 테스트 통과.

- 비로그인·일반 회원의 관리자 API 접근 차단, 관리자 허용
- 비로그인·회원·관리자의 브라우저 DB 직접 읽기/쓰기 차단 (권한 있는 Python API를 통해서만 접근)
- 회원 프로필 생성 및 중복 생성 차단, password·admin 등 임의 필드 저장 차단
- 서버 숙소 가격으로 계산, 임의 총액·회원 UID 무시, 신청 중복 방지
- 날짜·인원·숙소 상태 검증, 가격 변경 감지, 과거 예약 금액 보존
- 예약 소유권, 상태 전이, 수정 충돌, 변경 이력 검증
- 연결 여행지·숙소 숨김/비활성화와 과거 예약 보존
- 회원 본인의 예약 조회, 다른 회원의 예약 차단
- 서버 코드·환경 파일·규칙 파일의 정적 접근 차단
- 정지 회원 차단, 잘못된 로그인 자격증명 거부
- 관리자 여행지·숙소 등록/수정, 잘못된 이미지 주소·연결 여행지 차단
- 회원 프로필에 admin/role을 보내도 관리자 권한이 생기지 않음

## 브라우저 검증 (로컬 Emulator 데이터)

- 가입 성공 시 `가입 완료되었습니다.` 팝업 및 로그인 화면 이동
- 잘못된 비밀번호: `로그인 실패되었습니다.`
- 정상 로그인: `로그인 되었습니다.`
- 회원 로그인 후 예약·로그아웃 메뉴, 관리자·로그인 버튼 숨김
- 로그아웃: `로그아웃되었습니다`
- 비로그인 예약 클릭: `로그인후 예약하시오`
- 관리자 admin 입력과 Emulator Authentication 비밀번호 인증 → 성공 팝업 → html/admin.html
- 관리자 메뉴에 관리자로그아웃만 표시
- 관리자 여행지 등록 폼과 저장 성공, 예약 상세·상태 변경·확정 저장 확인
- 2박 예약 신청 시 서버 계산 금액 240,000원 저장 및 내 예약 표시
- 관리자 대시보드 스크린샷: docs/admin-preview.png (테스트 데이터)

기본 레이아웃과 모바일용 CSS는 구현했다. 이번 인증·관리 기능의 별도 모바일 실기기 검증은 수행하지 않았다.

## 실제 운영에서 미검증

추가 변경: 회원 본인 프로필 저장·조회·수정과 지정 관리자 회원 조회를 허용하는 규칙을 작성하고 `tests/test_profile_rules.py`의 8개 Emulator 테스트를 통과했다. 위 기존 12개 검증 기록은 Python API 구현 시점의 기록이며, 현재 회원 규칙의 정확한 허용 범위는 docs/MEMBER-RULES.md를 따른다.

실제 DB URL·관리자 UID·서버 Firebase 인증이 아직 준비되지 않았다. 실제 프로젝트에서 가입·로그인·예약 저장·관리자 CRUD 및 실제 DB Rules 배포는 수행하지 않았다. 실제 회원·예약 데이터를 생성하지 않았다. GitHub 업로드·외부 배포도 수행하지 않았다.

현재 Python 서버는 로컬 개발용이다. 운영 배포 전 HTTPS 호스팅, 개인정보 정책과 운영자 정보 확정 및 실제 프로젝트 테스트가 필요하다.
